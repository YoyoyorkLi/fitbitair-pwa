Privacy Policy

Pulse · last updated 3 September 2026

Pulse is a personal health dashboard built and run by one person for their own use. It has a single user. It is not a commercial service, it has no customers, and it does not accept sign-ups.

What it collects

With your explicit Google account consent, Pulse reads the following from the Google Health API:

  • Heart rate samples
  • Sleep sessions and their stages
  • Daily resting heart rate, heart rate variability, respiratory rate and blood oxygen
  • Step counts

It also records drink entries that you log yourself by tapping an NFC tag: a timestamp, a drink type, and a standard-drink count.

What it does with it

Computes derived metrics — strain, recovery, sleep score, sleep debt — and draws charts. Nothing else. There is no profiling, no advertising, no model training, and no automated decision-making.

Where it is stored

In a private Supabase (PostgreSQL) database owned by the operator, and in a local SQLite cache on the operator's own machine. Access is restricted by row-level security to a single authenticated account.

Google API credentials and the refresh token are held as encrypted environment variables on Vercel and GitHub, and in a local file with 0600 permissions. They are never sent to the browser.

Who it is shared with

Nobody. Health data is never sold, shared, transferred, or disclosed to any third party. There are no analytics, no trackers, no advertising networks, and no third-party scripts beyond the JavaScript library used to talk to the database.

Data is not used to build any product other than this dashboard, and never leaves the operator's own infrastructure.

Google user data

Pulse's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Google Health data is used solely to display the user's own metrics back to them.

Retention and deletion

Data is kept only while it is useful for trend analysis. You can revoke Pulse's access at any time at myaccount.google.com/permissions, which immediately stops all further access. To erase what has already been stored, delete the Supabase project — that removes every record permanently.

Cookies

None. A session token is kept in your browser's local storage so you do not have to sign in on every visit. It is never transmitted anywhere except the database that issued it.

Contact

Questions about this policy go to the operator at the support email listed on the Google consent screen.
